# Noether 언어 문서

이 문서 하나로 Noether의 문법과 동작을 전부 알 수 있습니다. 물리 지식은 필요 없습니다. `fermion`과 `boson`은 변수 종류의 이름일 뿐입니다. 이런 규칙이 나온 배경은 [개념 문서](concepts.md)에 따로 있습니다.

앞쪽은 쓰는 법을 쉽게 설명하고, 각 장 끝에 정확한 규칙을 적었습니다. 전체 문법은 [문법 정의](#문법-정의)에, 읽기의 정확한 계산은 [읽기](#읽기)에 있습니다.

## 빠른 시작

```noether
fermion n
|n> <- 3
while <n|~32 > 0
 emit <n|~32        # 3, 2, 1
 lower n
```

처음에는 세 가지만 기억하면 됩니다.

1. 값을 읽을 때는 `<x|~32`처럼 창 폭을 붙입니다. 안 붙이면 값이 흔들립니다.
2. 변수를 선언할 때 `@`를 생략하면 알아서 안전하게 떨어뜨려 놓습니다.
3. 들여쓰기는 1칸, 4칸, 9칸, 16칸입니다.

## 소스 코드의 모양

- 소스는 UTF-8 텍스트이고 한 줄에 문장 하나입니다. 문장을 여러 줄에 나누거나 한 줄에 둘을 쓸 수 없습니다.
- `#`부터 줄 끝까지는 주석입니다. 단, 문자열 안의 `#`는 그냥 글자입니다.
- 빈 줄과 주석만 있는 줄은 들여쓰기 규칙을 보지 않고 건너뜁니다.
- 줄 앞은 물론 코드 중간에도 탭을 쓸 수 없습니다. 문자열 안은 괜찮습니다.

**이름:** 영문자나 `_`로 시작하고 영문자, 숫자, `_`가 이어집니다. 대소문자를 구분합니다.

**키워드:** `field fermion boson stride mass path return if else while symmetry time translate in raise lower flip swap fuse emit emitc emitn absorb absorbc create annihilate`입니다. 예약어는 아니지만 변수 이름으로 쓰면 헷갈리고, `absorb`와 `absorbc`는 표현식에서 항상 입력으로 해석됩니다. 쓰지 않는 것을 권합니다.

**정수:** 10진수만 있습니다. 양수는 `9223372036854775807`까지, 음수 리터럴은 `-9223372036854775808`까지 쓸 수 있고, 넘으면 컴파일 오류입니다.

**문자열:** `"..."`이고 `emit`에서만 쓸 수 있습니다. 이스케이프는 `\n \t \r \0 \\ \"`만 있고, 다른 것은 컴파일 오류입니다.

**기호:** `<- <= >= == != < > | ~ ( ) [ ] , @ = + -`입니다. 공백은 토큰을 나눌 때만 의미가 있습니다.

주의할 함정이 하나 있습니다. `<-`는 항상 한 토큰입니다. `<x|~32 <-5`는 비교가 아니라 오류이므로 `<x|~32 < -5`처럼 띄어 씁니다.

## 들여쓰기

깊이 n의 줄은 정확히 n²칸의 공백으로 시작합니다.

| 깊이 | 0 | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|---|
| 공백 수 | 0 | 1 | 4 | 9 | 16 | 25 |

```noether
fermion a
if <a|~32 == 0
 if <a|~32 == 0
    if <a|~32 == 0
         emit 1      # 1
emit 2               # 2
```

- 블록은 `if`, `else`, `while`, `symmetry`, `path` 줄 바로 다음에 시작합니다. 콜론이나 괄호는 없습니다.
- 블록을 여는 줄 다음에는 반드시 한 단계 깊은 줄이 와야 합니다. 본문이 없으면 오류입니다.
- 들어갈 때는 한 단계씩만 들어갑니다. 나올 때는 몇 단계든 한 번에 나올 수 있습니다.
- 깊이는 코드 모양만이 아니라 동작에도 영향을 줍니다. 깊은 코드일수록 열을 많이 냅니다. [온도](#온도) 장을 보세요.

| 위반 | 메시지 |
|---|---|
| 공백 수가 제곱수가 아님 | `forbidden energy level` |
| 줄 앞에 탭 | `tabs are not quantized` |
| 블록을 여는 줄이 아닌데 깊어짐, 두 단계 이상 깊어짐 | `forbidden transition` |
| 블록 본문이 없음 | `forbidden transition` |

## 값과 주소

모든 값은 64비트 부호 있는 정수입니다. 연산이 범위를 넘으면 순환합니다. 다른 자료형은 없습니다.

메모리는 정수 주소가 무한히 이어진 직선이고, 변수는 그 위의 한 지점에 놓입니다. 음수 주소도 있습니다.

Noether에서 가장 중요한 규칙은 **표현식의 이름은 값이 아니라 주소**라는 것입니다.

| 표현식 | 결과 |
|---|---|
| `5`, `-5` | 정수 |
| `x` | x의 주소 |
| `x+100`, `x-100` | x의 주소에서 떨어진 주소. 오른쪽은 리터럴만 |
| `a` | 격자 a의 시작 주소 |
| `a[e]` | 원소 e의 주소. 범위를 벗어나도 계산만 하며 오류가 아님 |
| `a[e]+100` | 위 주소에서 떨어진 주소 |
| `(e)` | e의 값을 주소로 쓴 것 |
| `<주소\|~폭` | 그 주소를 읽은 값 |
| `<주소\|주소>~폭` | 그 주소를 읽은 값의 제곱. 양쪽은 똑같이 써야 함 |
| `f(인수, ...)` | 함수의 반환값 |
| `absorb`, `absorbc` | 입력에서 읽은 값 |

읽기의 주소 자리에는 위의 주소 형식이나 정수 리터럴을 쓸 수 있습니다. 정수 리터럴에는 `+`를 붙일 수 없습니다.

`-`는 리터럴 앞에서만 쓸 수 있습니다. 값 앞에 붙이는 `-x`나 `1 + 2` 같은 산술은 없습니다.

## 변수 선언

```text
fermion 이름 [ [개수] ] [ @ 위치 ] [ stride 간격 ] [ mass 질량 ]
boson   이름 [ [개수] ]   @ 위치   [ stride 간격 ] [ mass 질량 ]
```

| 종류 | 용도 | 위치 규칙 |
|---|---|---|
| `fermion` | 값 저장. 일반 변수로 쓴다 | `fermion`끼리 `2 × lambda`(기본 2048) 이상 떨어져야 함. `@` 생략 가능 |
| `boson` | 겹쳐서 계산에 쓴다 | 어디든 가능. `@` 필수 |

**위치:** `@ 4096`처럼 음이 아닌 정수를 쓰거나, `@ x`, `@ x+100`, `@ x-100`처럼 **먼저 선언된** 이름을 기준으로 씁니다. 격자 이름은 시작 주소를 뜻합니다.

**자동 배치:** `@`를 생략하면 지금까지 선언된 변수 중 가장 큰 주소에 `2 × lambda`를 더한 곳에 놓입니다. 첫 변수는 0입니다.

**격자(배열):** `a[8]`은 변수 8개입니다. 원소 j의 주소는 `시작 + j × stride`이고, `stride` 기본값은 `2 × lambda`입니다. 개수는 리터럴이고 0도 됩니다. 스칼라에 `stride`를 쓰면 무시됩니다.

```noether
fermion a[3] @ 100 stride 5000
emit a          # 100
emit a[2]       # 10100
emit a[9]       # 45100
```

**질량:** `mass`는 음이 아닌 정수이고 기본값은 0입니다. [온도](#온도)의 영향을 바꿉니다.

**선언 시점:** 전역 선언은 깊이 0에만 쓸 수 있습니다. 소스 어디에 있든 프로그램 시작 전에 소스 순서대로 만들어지고, 값은 0입니다. 그래서 선언보다 앞줄에서 써도 됩니다. 같은 이름을 두 번 선언하면 오류입니다.

```noether
emit <x|~32     # 0
fermion x
```

위치를 직접 지정해도 간격 검사는 똑같이 적용됩니다. 격자의 원소끼리도 마찬가지입니다. `fermion`을 가까이 두면 `Pauli violation` 컴파일 오류가 납니다. `boson`끼리나 `boson`과 `fermion`은 겹쳐도 됩니다.

## 설정

`field` 줄로 메모리 상수를 바꿉니다. 깊이 0이면 어디든 쓸 수 있고, 위치와 상관없이 프로그램 전체에 적용됩니다. 여러 줄이면 뒤의 값이 이깁니다.

```text
field hbar=16 lambda=1024 tau=64 tile=4096 tmin=1 seed=42
```

`seed`에는 숫자 대신 `random`을 쓸 수 있습니다. 다른 설정은 안 됩니다.

| 이름 | 기본값 | 제약 | 뜻 |
|---|---|---|---|
| `hbar` | 16 | 2의 거듭제곱, 2³² 이하 | 값 오차의 크기 |
| `lambda` | 1024 | 2의 거듭제곱, 2³² 이하 | 가장 차가울 때의 변수 폭 |
| `tau` | 64 | 2의 거듭제곱 | 온도가 절반이 되는 주기(틱) |
| `tile` | 4096 | 2의 거듭제곱 | 온도를 공유하는 주소 범위 |
| `tmin` | 1 | 2의 거듭제곱 | 최저 온도이자 초기 온도 |
| `seed` | 0 | 음이 아닌 정수, 또는 `random` | 난수 시드 |

**난수:** 기본은 시드가 고정이라 같은 프로그램은 항상 같은 결과를 냅니다. `field seed=random`을 쓰면 실행할 때마다 운영체제의 난수로 시드를 뽑으므로 결과를 예측할 수 없습니다. 난수 함수는 따로 없고, 날카로운 읽기가 난수원입니다. 폭 1로 읽으면 값이 `±hbar` 안에서 무작위로 움직입니다.

```noether
field seed=random
fermion coin
if <coin| > 0
 emit "앞면\n"
else
 emit "뒷면\n"
```

더 넓은 범위가 필요하면 여러 번 읽어서 값을 누적시킵니다. [guess.noe](../examples/guess.noe)가 예제입니다.

## 읽기

`<주소|~폭`으로 읽습니다. 폭은 1부터 2³²까지의 2의 거듭제곱 리터럴이고, 생략하면 1입니다.

### 쉬운 규칙

**좁게 읽으면 값이 흔들리고, 그 오차는 변수에 남습니다.** 읽기가 곧 쓰기가 되는 셈입니다. 기본 설정에서 온도가 낮을 때의 오차는 다음과 같습니다.

| 폭 | 32 이상 | 16 | 8 | 4 | 2 | 1 |
|---|---|---|---|---|---|---|
| 오차 범위 | 없음 | ±1 | ±2 | ±4 | ±8 | ±16 |

**넓게 읽으면 이웃도 함께 읽힙니다.** 읽는 지점에서 닿는 변수는 모두 결과에 더해지고, 멀수록 적게 반영됩니다.

```noether
fermion a @ 0
fermion b @ 4096
|a> <- 1000
|b> <- 1000
emit <a|~32       # 1000
emit <a|~8192     # 1500: b는 절반만 더해진다
```

그래서 평소에는 `~32`로 읽고 변수를 떨어뜨려 두면 됩니다. 빈 곳을 읽으면 0이고, 읽기 자체는 절대 오류를 내지 않습니다.

### 정확한 계산

기호를 먼저 정합니다. `x`는 읽는 주소이고 창 폭은 `2^k`입니다. `H = log₂ hbar`, `L = log₂ lambda`입니다.

읽기 한 번은 다음 순서로 실행됩니다.

1. 틱을 1 늘립니다.
2. `x`가 속한 타일에 마찰 열을 넣습니다. 빈 주소를 읽어도 넣습니다.
3. 읽는 쪽 필드의 모든 변수 `p`에 아래 계산을 합니다. 순서는 결과에 영향이 없습니다.
4. 결과는 `acc >> q`를 64비트로 순환시킨 값입니다. `q = max(k, L)`이고 시프트는 내림입니다.

```text
d = |x - p.주소|
t = floor(log2(p의 타일 온도))
s = max(0, L - floor((t + p.mass) / 2))    # 변수 폭은 2^s
r = max(k, s)                              # 도달 범위는 2^r
if d >= 2^r: 이 변수는 건너뜀

e = H - min(k, s)
if e >= 0:                                 # 값이 흔들린다
    dv = 2^e
    p.값 += 노이즈(p, dv)                  # -dv 이상 dv 이하
    p.시계 += 1

acc += p.값 * (2^r - d) * 2^(q - r)        # 내림은 마지막에 한 번만
```

풀어 쓰면 이렇습니다.

- 변수 폭은 `σ = lambda / 2^⌊(⌊log₂ 온도⌋ + mass) / 2⌋`이고 최소 1입니다.
- 오차 범위는 `±⌊hbar / min(폭, σ)⌋`입니다. 이 값이 0이면 흔들리지 않습니다.
- 변수는 거리 `d`가 `R = max(폭, σ)`보다 작을 때만 결과에 들어가고, 그 값의 `(R - d) / R`만큼 더해집니다.
- 변수 하나의 한 번 읽기 오차는 `hbar`를 넘지 않습니다.
- 흔들린 값이 곧 새 값이므로, 오차가 생기면 그 변수가 실제로 바뀝니다. 가중치도 바뀐 값에 적용됩니다.
- 각 변수의 `σ`와 오차는 그 변수 자신의 타일 온도로 계산합니다. 마찰 열만 `x`의 타일로 갑니다.

**노이즈:** 시드가 고정이면 같은 프로그램의 결과는 항상 같습니다. 노이즈는 다음으로 정해집니다.

```text
mix(z):  z = (z ^ (z >> 30)) * 0xBF58476D1CE4E5B9
         z = (z ^ (z >> 27)) * 0x94D049BB133111EB
         return z ^ (z >> 31)

h = mix(seed ^ (p.주소 * 0x9E3779B97F4A7C15)
             ^ (p.시계 * 0xC2B2AE3D27D4EB4F)
             ^ (호출번호 * 0x165667B19E3779F9))
노이즈 = (((h >> 32) * (2*dv + 1)) >> 32) - dv
```

위의 곱셈과 `mix`는 부호 없는 64비트로 순환하고, 마지막 줄의 곱셈만 128비트로 계산합니다. `>>`는 논리 시프트입니다. 변수의 시계는 0에서 시작해 흔들릴 때만 늘어납니다. 호출번호는 전역 변수에서 0이고, 함수 안 변수는 그 호출의 번호입니다. 호출번호는 프로그램 시작부터 1, 2, 3으로 매겨집니다.

**세기 읽기:** `<a|a>~폭`은 위 규칙으로 한 번 읽은 값을 제곱합니다. 틱과 열도 읽기 한 번 분량입니다.

## 온도

메모리는 `tile` 크기로 나뉩니다. 주소 `x`의 타일은 `floor(x / tile)`번입니다. 타일마다 온도가 있고 `tmin`에서 시작합니다. 함수 호출마다 타일을 따로 하나 씁니다.

### 틱

틱은 프로그램의 시계이고 0에서 시작합니다. [대칭 블록](#대칭-블록) 밖에서 아래 연산이 실행될 때마다 1 늘어납니다.

읽기, 덮어쓰기, `raise`, `lower`, `flip`, `swap`, `fuse`, `create`, `annihilate`.

`emit`, `absorb`, 함수 호출, 조건 분기 자체는 틱을 쓰지 않습니다. 조건 안의 읽기는 셉니다.

### 열이 나는 경우

| 연산 | 열 | 들어가는 타일 |
|---|---|---|
| 읽기 | `(n+1)²` | 읽는 주소의 타일 |
| 덮어쓰기 | `(n+1)²` + `popcount(옛값 XOR 새값)` | 변수의 타일 |
| `create` | `(n+1)²` | 그 주소의 타일 |
| `annihilate` | `(n+1)²` + `popcount(값)` | 그 주소의 타일 |
| `raise`, `lower`, `flip`, `swap`, `fuse` | 없음 | 없음 |

`n`은 그 연산을 포함한 문장의 들여쓰기 깊이입니다. `if`와 `while`의 조건은 그 줄의 깊이를 씁니다. 함수 호출의 인수는 호출하는 쪽 문장의 깊이를 씁니다. `popcount`는 1인 비트의 수입니다.

```noether
fermion x
|x> <- 7          # 틱 1, 온도 1 + 1 + 3 = 5
emit <x|~32       # 7: 틱 2, 온도 6
raise x           # 틱 3, 열 없음
emit <x|~32       # 8: 틱 4, 온도 7
```

온도의 상한은 2⁶²입니다.

### 식는 규칙

`tau` 틱마다 모든 타일의 온도가 절반이 됩니다(내림). 틱이 `tau`의 배수를 지날 때마다 일어나고 `tmin` 아래로는 내려가지 않습니다. 정확히는 타일을 볼 때마다 다음을 먼저 적용합니다.

```text
now = floor(틱 / tau)
if now > 타일.epoch:
    타일.온도 = max(tmin, 타일.온도 >> min(now - 타일.epoch, 63))
    타일.epoch = now
```

### 온도의 효과

기본 설정, `mass 0`의 값입니다.

| 온도 | 1~3 | 4~15 | 16~63 | 64~255 | 256~1023 | 1024~4095 | 4096~16383 | ~65535 | ~262143 | ~1048575 | 그 이상 |
|---|---|---|---|---|---|---|---|---|---|---|---|
| 변수 폭 | 1024 | 512 | 256 | 128 | 64 | 32 | 16 | 8 | 4 | 2 | 1 |
| `~32` 읽기 오차 | 없음 | 없음 | 없음 | 없음 | 없음 | 없음 | ±1 | ±2 | ±4 | ±8 | ±16 |

- **임계 온도:** 넓은 창으로 읽어도 값이 흔들리기 시작하는 온도입니다. `2^(2(L-H) - mass)`이고 기본값은 4096입니다. `mass`가 1 늘 때마다 절반이 됩니다.
- **뜨거우면** 변수 폭이 줄어 이웃과 안 섞이지만 값이 흔들립니다.
- **차가우면** 값은 정확하지만 변수 폭이 넓어져 가까운 변수와 섞입니다. 온도가 낮을수록 같은 읽기의 결과가 달라질 수 있습니다.

```noether
field seed=7
boson p @ 100000
boson q @ 100300
fermion c @ 0
|p> <- 1000
|q> <- 2000
emit <p|~32        # 1000: 온도 16 이상이라 폭 256, q에 안 닿음
|c> <- 3000
while <c|~32 > 0
 lower c
emit <p|~32        # 2414: 식어서 폭 1024, q가 724/1024만큼 섞임
```

`fermion` 간격 규칙을 지키고 창을 `2 × lambda` 이하로 쓰면, `fermion`끼리는 어떤 온도에서도 섞이지 않습니다. 섞임은 간격 규칙이 없는 `boson`에서 생깁니다.

### 과열 피하기

- 자주 쓰는 변수를 서로 다른 타일에 놓습니다.
- 덮어쓰기 대신 `raise`, `lower`, `swap`을 씁니다.
- 뜨거운 코드를 깊이 낮은 곳으로 옮깁니다.
- `field tau=`를 줄이면 빨리 식습니다.

덮어쓰기를 쓰지 않는 프로그램의 최대 깊이가 `n`이라면, 다음 조건에서 온도는 절대 임계에 닿지 않습니다.

```text
2 × tau × (n+1)² + tmin < 임계 온도
```

틱마다 들어오는 열이 `(n+1)²` 이하이고, 한 주기에 쌓인 열이 절반씩 줄기 때문입니다. 이 조건에서 `fermion`, 넓은 창, `raise`, `lower`, 조건문만 쓰면 값은 항상 정확합니다. 값의 크기가 무한하다고 보면 이것만으로 2-카운터 머신을 만들 수 있으므로 언어는 튜링 완전합니다. 실제 값은 다른 언어처럼 64비트로 제한됩니다.

## 값 바꾸기

대상은 세 가지로 씁니다.

| 대상 | 뜻 |
|---|---|
| `x` | 그 변수. 같은 자리에 변수가 여럿이어도 정확히 x |
| `a[e]` | 격자 원소. 범위 밖이면 실행 오류 |
| `(e)` | 주소가 정확히 e인 전역 변수 중 가장 먼저 만들어진 것. 없으면 실행 오류 |

격자 이름만 대상으로 쓰면 실행 오류입니다.

| 문장 | 뜻 |
|---|---|
| `\|대상> <- 값` | 덮어쓰기. 값은 정확히 저장되고 오차가 없음 |
| `raise 대상` | 1 증가 |
| `lower 대상` | 1 감소 |
| `flip 대상` | 부호 반전 |
| `swap 대상 대상` | 두 변수의 값 교환. 변수의 시계는 그대로 |
| `fuse 대상 대상` | 첫째에 둘째를 더함. 같은 필드, 같은 주소가 아니면 실행 오류 |

## 계산하기

`+`, `-`, `*`, `/` 연산자는 없습니다. 읽기 규칙으로 계산합니다.

**덧셈:** 같은 자리에 변수를 겹쳐 놓고 그 자리를 읽습니다. 가중치가 1이라 정확합니다.

```noether
boson a @ 8192
boson b @ 8192
|a> <- 3
|b> <- 4
emit <8192|~32      # 7
```

**뺄셈:** 한쪽을 뒤집고 읽습니다.

```noether
boson a @ 8192
boson b @ 8192
|a> <- 10
|b> <- 3
flip b
emit <8192|~32      # 7
```

**2의 거듭제곱으로 나누기:** 중심에서 벗어나 읽습니다. 폭 1024로 768 벗어나면 `(1024-768)/1024 = ¼`입니다. 폭이 `lambda` 이상이어야 온도와 상관없이 일정합니다.

```noether
fermion x
|x> <- 100
emit <x+768|~1024   # 25
emit <x+512|~1024   # 50
```

**곱셈:** `ab = ((a+b)² - (a-b)²) / 4`를 씁니다.

```noether
path mul(a, b)
 boson p @ a
 fermion s
 boson u @ s
 |p> <- <b|~32          # a 자리는 이제 a+b
 |s> <- <a|a>~32        # (a+b)²
 flip p                 # a 자리는 이제 a-b
 |u> <- <a|a>~32        # (a-b)²
 flip u                 # s 자리는 이제 4ab
 return <s+768|~1024    # ¼을 읽는다

emit mul(6, 7)          # 42
```

**되돌릴 수 있는 덧셈:** 같은 자리의 두 변수는 `fuse`로 더할 수 있습니다. 열이 나지 않습니다.

## 제어문

```text
if 값 비교 값
 ...
else
 ...

while 값 비교 값
 ...
```

비교는 `<`, `>`, `<=`, `>=`, `==`, `!=` 중 하나이고 부호 있는 비교입니다. 조건에는 비교가 꼭 있어야 합니다. `if <x|~32`처럼 값만 쓸 수 없고, `and`, `or`도 없습니다. `else`는 `if`와 같은 깊이에 씁니다. `break`나 `continue`는 없습니다.

`while`의 조건은 반복마다 다시 평가되므로 읽기도 다시 일어나고 열도 다시 납니다.

## 함수

함수는 `path`로 만듭니다. 깊이 0에만 쓸 수 있고, 선언보다 앞에서 호출해도 됩니다. 재귀도 됩니다.

```noether
path twice(a)
 boson b @ a
 |b> <- <a|~32
 return <a|~32

emit twice(21)      # 42
```

- 호출은 값으로 쓰거나 `f(1)`처럼 문장으로 씁니다. 인수 개수가 다르면 컴파일 오류입니다.
- `return 값` 또는 `return`으로 돌아옵니다. 값이 없거나 끝까지 가면 0을 돌려줍니다. 함수 밖의 `return`은 오류입니다.
- 함수 이름이 겹치면 컴파일 오류입니다.

**함수의 메모리:** 호출마다 그 호출만의 메모리가 새로 생깁니다.

- 주소가 0부터 시작하는 별도의 축입니다. 전역 주소와 관계없습니다.
- 매개변수는 왼쪽부터 자동 배치된 `fermion`입니다(0, 2048, 4096...). 이어서 지역 변수가 소스 순서대로 만들어집니다.
- 지역 변수 선언은 본문 깊이 1에만 쓸 수 있습니다. 위치와 상관없이 호출 시작에 만들어지고 값은 0입니다.
- 위치 `@`의 이름은 이미 선언된 지역 이름만 됩니다. 전역 이름은 안 됩니다. 숫자는 그 호출의 축 위 주소입니다.
- 지역 격자도 쓸 수 있습니다.
- 파울리 규칙은 같은 호출의 `fermion`끼리 적용됩니다.
- 타일은 함수 전체가 하나입니다. 온도 `tmin`으로 시작하고 끝나면 사라집니다. 호출한 쪽을 데우지 않습니다.

**이름 해석:** 지역 이름이 전역 이름을 가립니다. 가려지지 않은 전역 변수는 함수 안에서도 읽고 쓸 수 있습니다.

```noether
fermion g
|g> <- 3
path f()
 raise g
 return <g|~32
emit f()            # 4
```

**지역 변수에는 주소가 없습니다.** `a`나 `a[1]`을 값으로 쓰면 컴파일 오류입니다. `<a|~32`처럼 읽기와 대상으로만 씁니다. `<a+768|~1024`처럼 변위도 됩니다. `(e)`와 숫자 주소 `<8192|`는 함수 안에서도 항상 전역을 가리킵니다.

재귀 깊이는 네이티브 스택(1GiB)으로 제한됩니다.

## 포인터

주소는 정수이므로 변수에 담을 수 있습니다. `(값)`이 역참조입니다.

```noether
fermion x
fermion p
|x> <- 7
|p> <- x                 # x의 주소를 담는다
emit <(<p|~32)|~32       # 7
|(<p|~32)> <- 8          # x에 8을 쓴다
emit <x|~32              # 8
```

- `<(e)|`는 그 주소를 읽기 규칙대로 읽습니다. 변수가 없어도 됩니다.
- `|(e)>`는 주소가 정확히 일치하는 변수가 있어야 합니다.
- `(e)+100`처럼 변위를 붙일 수 있습니다.

## 동적 변수

실행 중에 변수를 만들고 없앨 수 있습니다.

```noether
create fermion @ 1000000
|(1000000)> <- 5
emit <(1000000)|~32      # 5
annihilate 1000000
```

`create 종류 @ 값`은 값이 0이고 `mass 0`인 변수를 만듭니다. 이름이 없으므로 `(주소)`로 씁니다.

- 주소는 **진공 경계** 이상이어야 합니다. 진공 경계는 `(floor((가장 큰 전역 주소 + 2 × lambda) / tile) + 1) × tile`입니다. 전역 변수가 없으면 가장 큰 주소를 -1로 칩니다.
- `fermion`을 만들 때 거리 `2 × lambda` 안에 다른 `fermion`이 있으면 실행 오류입니다.
- 같은 주소에 `boson`을 여럿 만들 수 있습니다.

`annihilate 값`은 진공 경계 이상에서 주소가 정확히 일치하는 변수 중 가장 먼저 만들어진 것을 없앱니다. 없으면 실행 오류입니다. 선언한 변수는 없앨 수 없습니다.

## 대칭 블록

블록에 대칭을 선언하면 컴파일러가 제약을 검사하고 더 빠른 코드를 만듭니다. 어기면 컴파일 오류입니다. 두 블록의 공통 규칙은 다음과 같습니다.

- 블록 안에서는 **틱이 멈춥니다.** 앞의 틱 규칙이 적용되지 않고, 나갈 때 몰아서 더하지도 않습니다.
- 틱이 멈추므로 온도도 식지 않습니다.
- 함수 호출과 입력(`absorb`, `absorbc`)은 어디에도 쓸 수 없습니다.
- 값의 정확성 규칙은 그대로입니다. 뜨겁거나 창이 좁으면 값이 흔들립니다.

### symmetry time

되돌릴 수 있는 연산만 쓰는 블록입니다. 안에서는 읽기도 열을 내지 않습니다. 블록 전후의 온도가 같습니다.

```noether
fermion i
|i> <- 1000
symmetry time
 while <i|~32 > 0
    lower i
emit <i|~32         # 0
```

| 허용 | 금지 |
|---|---|
| `raise`, `lower`, `flip`, `swap`, `fuse` | 덮어쓰기 |
| `if`, `else`, `while` | `emit`, `emitc`, `emitn` |
| 조건과 첨자 안의 읽기 | `create`, `annihilate`, `return` |
| 중첩된 `symmetry time` | `symmetry translate` |

### symmetry translate

```text
symmetry translate k in a
 ...
```

격자 `a`의 원소마다 본문을 실행합니다. `k`는 0부터 길이-1까지 순서대로 늘어납니다. `a`는 전역 격자여야 합니다.

```noether
fermion a[4] @ 0 stride 4096
boson   b[4] @ a stride 4096
fermion c[4] @ 65536 stride 4096
|a[3]> <- 4
|b[3]> <- 40
symmetry translate k in a
 |c[k]> <- <a[k]|~32
emit <c[3]|~32      # 44
```

- 격자 첨자는 정확히 `k`만 됩니다. `a[k]`는 되고 `a[<i|~32]`는 안 됩니다. 쓰는 격자는 전역이고 길이가 `a` 이상이어야 합니다.
- `k`는 첨자로만 쓸 수 있습니다. 값으로 쓰거나 읽을 수 없습니다.
- 값을 바꿀 수 있는 것은 `격자[k]`뿐입니다. 스칼라는 읽기만 합니다.
- 쓸 수 있는 문장은 덮어쓰기, `raise`, `lower`, `flip`, `swap`, `fuse`, `if`, `else`입니다.
- `while`, 다른 `symmetry`, 출력, `create`, `annihilate`, `return`, `(e)` 주소는 금지입니다.
- 마찰과 덮어쓰기 열은 평소대로 계산하지만 바로 넣지 않고, 블록이 끝날 때 한꺼번에 넣습니다. 그래서 블록 안에서는 온도가 진입 시점 그대로입니다.

### 언제 빨라지나

컴파일러는 대칭 블록을 두 벌 만들고 진입 시 고릅니다. 두 벌의 결과는 항상 같습니다. 빠른 코드는 다음 조건을 모두 만족할 때 만들어지고 실행됩니다.

- 블록의 모든 읽기가 `hbar`보다 넓은 창을 씁니다.
- 어떤 온도에서도 어떤 변수가 그 읽기에 닿는지 컴파일 시점에 정해집니다. 즉 `(e)` 주소가 없고, 중심이 아닌 곳을 읽는 경우 창이 변수의 최대 폭 이상입니다. 격자는 원소마다 자기 자신과 겹친 원소만 읽어야 합니다.
- 진입 시점에 읽는 변수의 타일이 모두 임계 온도 아래입니다.

`--stats`로 빠른 코드가 생긴 블록 수를 볼 수 있습니다.

## 입출력

| 문법 | 뜻 |
|---|---|
| `emit 값` | 10진수와 줄바꿈을 출력 |
| `emitn 값` | 10진수만 출력. 줄바꿈 없음 |
| `emit "문자열"` | 문자열을 그대로 출력. 줄바꿈 없음 |
| `emitc 값` | 값의 하위 8비트를 1바이트로 출력 |
| `absorb` | 입력에서 한 줄을 읽어 앞뒤 공백을 지우고 정수로 변환. 실패하거나 입력이 끝나면 0 |
| `absorbc` | 1바이트를 읽음. 입력이 끝나면 -1 |

`emit` 계열은 문장이고 `absorb`와 `absorbc`는 표현식입니다.

`emitc`는 값을 글자 코드로 출력합니다. ASCII 코드를 이어서 내보내면 문자열이 됩니다.

```noether
emitc 72
emitc 105
emitc 10          # Hi와 줄바꿈
emitn 7
emit " x "
emitn 6
emit " = 42\n"    # 7 x 6 = 42
```

UTF-8 바이트를 차례로 내보내면 한글도 출력됩니다.

**문자열 저장:** 문자열 변수는 없습니다. 문자열 리터럴은 `emit`에서만 쓸 수 있고, 입력받은 글자를 저장하려면 격자에 바이트로 넣습니다. [name.noe](../examples/name.noe)가 예제입니다.

## 실행 순서

- 프로그램은 전역 변수를 만든 뒤 깊이 0의 문장을 위에서 아래로 실행합니다. 함수 정의는 실행되지 않습니다.
- 표현식은 왼쪽에서 오른쪽으로 평가합니다. 읽기는 주소의 안쪽 표현식을 먼저 평가합니다.
- 덮어쓰기는 대상 확정(첨자 평가, 범위 검사), 오른쪽 값 평가, 틱 증가, 열, 저장 순입니다.
- `swap`과 `fuse`는 첫째 대상, 둘째 대상 순으로 확정합니다.
- 비교는 왼쪽 값, 오른쪽 값 순으로 평가합니다.
- 호출은 인수를 왼쪽부터 평가한 뒤 호출번호를 하나 늘리고 메모리를 만듭니다.

## 문법 정의

위 규칙의 전체 문법입니다. `BLOCK`은 한 단계 깊어진 문장들입니다.

```ebnf
program   = { field | decl | path | stmt } ;
field     = "field" { NAME "=" (INT | "random") } ;
decl      = ("fermion" | "boson") NAME [ "[" INT "]" ] [ "@" place ]
            { "stride" INT | "mass" INT } ;
place     = INT | NAME [ ("+" | "-") INT ] ;
path      = "path" NAME "(" [ NAME { "," NAME } ] ")" BLOCK ;

stmt      = ket "<-" value
          | ("raise" | "lower" | "flip") target
          | ("swap" | "fuse") target target
          | "if" cond BLOCK [ "else" BLOCK ]
          | "while" cond BLOCK
          | "symmetry" "time" BLOCK
          | "symmetry" "translate" NAME "in" NAME BLOCK
          | "emit" (value | STRING)
          | "emitc" value
          | "emitn" value
          | "create" ("fermion" | "boson") "@" value
          | "annihilate" value
          | "return" [ value ]
          | call ;

ket       = "|" target ">" ;
target    = NAME | NAME "[" value "]" | "(" value ")" ;
cond      = value ("<" | ">" | "<=" | ">=" | "==" | "!=") value ;
value     = INT | "-" INT | bra | intensity | call | addr
          | "absorb" | "absorbc" ;
bra       = "<" addr "|" [ window ] ;
intensity = "<" addr "|" addr ">" [ window ] ;
window    = "~" INT ;
call      = NAME "(" [ value { "," value } ] ")" ;
addr      = INT | target [ ("+" | "-") INT ] ;
```

`<주소|` 바로 뒤에 이름, 숫자, `(`가 오면 세기 읽기로 해석합니다.

## 오류

컴파일 오류는 실행 전에 나고 종료 코드는 2입니다.

| 메시지에 포함된 말 | 원인 |
|---|---|
| `forbidden energy level` | 공백 수가 제곱수가 아님 |
| `forbidden transition` | 들여쓰기 단계가 맞지 않거나 본문이 없음 |
| `tabs are not quantized`, `bad character` | 쓸 수 없는 문자 |
| `does not fit in 64 bits` | 정수가 범위를 넘음 |
| `unknown escape`, `unterminated string` | 문자열 오류 |
| `is not a power of two` | 창이나 `field` 값이 2의 거듭제곱이 아니거나 범위를 넘음 |
| `limited to 2^32` | `lambda`나 `hbar`가 너무 큼 |
| `only seed can be random` | `seed` 외의 설정에 `random`을 씀 |
| `unknown field parameter`, `unknown attribute`, `unknown symmetry` | 없는 설정 이름 |
| `unknown name`, `unknown path` | 없는 변수나 함수 |
| `declared twice` | 이름 중복 |
| `used with the wrong shape` | 격자가 아닌 것에 첨자를 씀 |
| `takes N arguments` | 인수 개수가 다름 |
| `a boson must be placed` | `boson`에 `@`가 없음 |
| `Pauli violation` | `fermion`끼리 너무 가까움 |
| `declarations only at the top of a path` | 블록 안에서 선언함 |
| `belongs at the top level` | `field`나 `path`를 블록 안에 씀 |
| `return outside a path` | 함수 밖의 `return` |
| `closed system` | 지역 변수의 주소를 쓰거나 대칭 블록에서 호출, 입력을 씀 |
| `symmetry time broken`, `symmetry translate broken` | 대칭 블록에서 금지된 것을 씀 |
| `may only be used as a subscript` | `k`를 첨자 밖에서 씀 |
| `is shorter than the sweep` | 격자 길이가 모자람 |
| `is not a global lattice` | `translate` 대상이 전역 격자가 아님 |
| `intensity needs the same address` | 세기 읽기의 양쪽이 다름 |
| `expected`, `unexpected`, `cannot start a statement` | 그 외 문법 오류 |

실행 오류는 메시지를 표준 오류로 내고 종료 코드 3으로 끝납니다. 그때까지의 출력은 남습니다.

| 메시지 | 원인 |
|---|---|
| `index N is outside lattice` | 대상의 첨자가 범위 밖 |
| `a lattice used as a single packet` | 격자 이름을 대상으로 씀 |
| `write into vacuum` | `(e)` 대상 주소에 변수가 없음 |
| `fuse needs two packets at the same centre` | `fuse`의 두 변수가 다른 자리에 있음 |
| `create at N is below the vacuum base` | 진공 경계 아래에 `create` |
| `Pauli violation at N` | `create`한 `fermion`이 다른 `fermion`과 너무 가까움 |
| `nothing to annihilate` | 없앨 변수가 없음 |

## 컴파일러

```bash
noetherc 파일.noe -o 출력.exe
```

`-o`를 생략하면 소스와 같은 이름의 `.exe`를 만듭니다.

| 옵션 | 뜻 |
|---|---|
| `--run` | 실행 파일을 만들지 않고 바로 실행 |
| `--thermo` | 온도를 기록하고 끝날 때 요약을 표준 오류로 출력 |
| `--stats` | 읽기 수, 증명 못 한 읽기 수, 대칭 블록 수, 빠른 코드가 생긴 블록 수 출력 |
| `--no-symmetry` | 대칭 블록의 빠른 코드를 만들지 않음 |
| `--no-isolate` | 모든 읽기를 일반 경로로 실행 |

시드가 고정이면 어떤 옵션을 써도, `--run`으로 실행해도 프로그램 결과는 같습니다.

종료 코드는 0 정상, 2 컴파일 오류, 3 실행 오류, 64 잘못된 명령행, 66 소스를 읽지 못함, 70 코드 생성이나 링크 실패, 73 출력 파일을 쓰지 못함입니다.

**온도 파일:** `--thermo`는 `출력.thermo.csv`를 만듭니다. `--run`과 함께 쓰면 `-o`로 준 이름을 기준으로 합니다.

```text
tick,tile,temperature
1,0,5
2,0,6
```

- 열이 들어갈 때마다 한 행이 생깁니다.
- `tile`은 타일의 시작 주소이고, 함수 호출의 타일은 `frame`입니다.
- `symmetry translate`의 열은 블록이 끝날 때 기록됩니다.
- 행이 2²⁰개를 넘으면 전체 기간에서 고르게 절반씩 솎아냅니다. 요약의 최고 온도와 비트 수는 솎아내도 정확합니다.

**플레이그라운드:** 브라우저 실행에는 몇 가지 한도가 있습니다. 실행 문장 수 6천만, 출력 1MiB, 온도 기록 4만 행이고, 재귀 깊이는 브라우저 스택에 달렸습니다. 한도 외의 동작은 같습니다.

터미널 창은 프로그램이 입력을 읽으려 할 때 입력을 받습니다. Enter로 한 줄을 보내고, Ctrl+D로 입력을 끝냅니다. 내부적으로는 입력이 늘 때마다 프로그램을 처음부터 다시 실행합니다. 같은 입력이면 결과가 같으므로 화면에는 이어서 실행되는 것처럼 보입니다. `seed=random` 프로그램은 실행 버튼을 누를 때 시드를 한 번 뽑아 그 실행이 끝날 때까지 유지합니다.

그래프의 온도와 파동 보기는 전환할 수 있습니다. 파동 보기는 슬라이더로 틱을 옮기거나 재생할 수 있습니다. 전역 변수를 최대 48개까지 보여 주며 스칼라가 먼저입니다. 함수의 지역 변수와 `create`로 만든 변수는 나오지 않습니다. 삼각형의 높이는 값, 폭은 변수 폭, 색은 온도이고, 진한 선은 각 지점의 합입니다. 멀리 떨어진 변수 사이의 간격은 줄여서 그립니다.
